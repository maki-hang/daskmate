# SQLite 数据迁移

本文记录 0.5 阶段的 SQLite 存储改造。0.6 的运行实现已由 Rust 接管，数据库结构继续兼容；当前构建与模块说明见 [Rust 迁移](rust-migration.md)。下文 Node/Electron 实现仍保留用于兼容回归。

桌面框架和界面保持 Electron + HTML/CSS/JavaScript。本次仅迁移持久化层，采用 Node/Electron 内置的 `node:sqlite`，源码命令要求 Node.js 22.13+。安装版使用自带 Electron 运行时，用户无需另外安装 Node.js 或数据库服务；可选 Claude 状态行脚本仍需要 Node.js。

## 数据结构

数据库位于原用户数据目录的 `assistant.sqlite`，使用 `PRAGMA user_version` 管理结构版本，当前为 1。

| 表 | 用途 |
| --- | --- |
| `notes` | 便签，日期、时间和内容为独立列 |
| `reminders` | 提醒时间、重复规则、启用/完成/未读状态；可选外键关联便签 |
| `repositories` | 面板中启用的仓库、作者身份和同步状态 |
| `git_archives`、`commits` | 按仓库和提交哈希去重的持久历史 |
| `settings` | 设置键值，包括 Agent 选择、角色绑定和桌宠位置 |
| `skins` | 导入角色的元数据及本地素材位置 |
| `metadata` | 数据版本、日历迁移版本及一次性初始化标记 |

Git 查询在 SQL 中完成作者、仓库、日期筛选和分页，日期范围按查询时的本机时区计算。Unicode 搜索维持 JavaScript 的小写转换语义，百分号和下划线按字面搜索。提交表有时间、仓库、作者邮箱/姓名索引；任意内容子串搜索仍可能扫描匹配范围，未引入全文搜索引擎。

`Store.update` 保留现有同步接口，在事务中读取当前状态、执行修改，仅写入变化的记录。Git 提交与仓库计数/同步状态在同一事务中提交。数据库不存整份 `assistant.json`。设置值、嵌套形象元数据和未知旧字段用 JSON 编码，便于无损兼容；常用业务字段为独立列。

## 首次导入

1. 沿用现有数据目录选择规则，并识别 SQLite 文件，兼容旧品牌目录和两个环境变量。
2. 创建数据库结构，在 `BEGIN IMMEDIATE` 事务内检查初始化标记。
3. 读取旧 `assistant.json`；主文件无法解析时尝试 `.bak`。两者都不可用时停止迁移，不创建空白业务数据覆盖旧记录。
4. 补齐旧日历结构，导入便签、提醒、设置、仓库和形象。扫描并导入数据目录内全部 `git-*.json`，包括已从面板移除的仓库。
5. 检查记录数量、提交去重数量和数据库约束，写入初始化标记并提交。任意步骤失败都回滚业务数据与标记；修复旧文件后下次启动重试。
6. 保留旧 JSON 和旧备份的原始字节。初始化成功后只使用 SQLite，不再重复导入或回写 JSON。

从面板移除仓库只删除启用记录，保留提交存档；重新添加相同仓库后可以继续使用历史。Git 同步只增加/更新可达提交，不清理已归档历史。动画文件、`skin.json`、Claude 状态行输入快照和可重新获取的版本缓存仍使用文件。

## 事务、备份与恢复

每个写事务启用外键检查和 `synchronous=FULL`，锁等待上限为 5 秒。提醒状态提交后才发送通知，保持原有重启补发和去重语义。

启动完成和正常退出时使用 `VACUUM INTO` 生成一致快照，先写 `assistant.sqlite.bak.tmp`，成功后替换 `assistant.sqlite.bak`。快照并非每次编辑都生成，可能落后于当前数据库。异常退出后由 SQLite 的事务日志恢复；系统通知与数据库不能组成同一个事务，提交后、发通知前崩溃的提醒仍可在未读列表找回。

启动时执行 `quick_check`。只在确认为数据库损坏、且备份通过检查并已完成初始化时自动恢复，并保留原数据库的 `.damaged-*` 副本。主数据库丢失但备份仍在时也先验证并恢复备份，不创建空库覆盖它。目录选择同时识别 `assistant.sqlite.bak`。文件锁、权限错误和更高的结构版本都直接报错，不用旧备份替换有效数据库。数据库损坏后也不会静默回退到过时的旧 JSON。

手动备份应先从托盘退出程序，再复制整个数据目录，包括数据库与素材文件。需要恢复时先另存当前整个目录，再在退出状态下用备份的完整目录恢复。旧 JSON 仅是迁移前快照，运行旧版不会看到迁移后新增的内容。

## 验证

`npm.cmd test` 覆盖一次性导入、原文件保留、损坏 JSON 回退、导入失败后重试、SQL 事务回滚、外键约束、跨连接更新、数据库损坏恢复、未来版本拒绝、Unicode/日期/作者查询、稳定分页以及进程直接退出后的提醒去重。原有真实 Git 仓库测试继续覆盖分支删除后的历史保留。

`npm.cmd run test:ui` 从旧 JSON 启动，验证 SQLite 文件生成、原 JSON 保留，以及便签、提醒、Git、角色导入、语言设置、重启和后台通知的完整界面流程。
